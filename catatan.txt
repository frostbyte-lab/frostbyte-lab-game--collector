CATATAN EMULATOR STATEFUL API LOKAL
Repository: frostbyte-lab-game--collector
Versi: stateful-v1

1. TUJUAN
Emulator ini menyediakan backend lokal sederhana untuk preview offline. Endpoint yang ditangani adalah init, balance, dan spin, dengan tambahan session/verifysession agar alur awal game dapat dimulai. Emulator ini bukan backend produksi dan bukan simulasi aturan game asli.

2. ENDPOINT YANG DIDUKUNG
Route /init, /gameinfo, dan /gamedata menghasilkan konfigurasi game serta saldo awal. Route /balance dan /gamewallet menghasilkan saldo terbaru. Route /spin, /bet, dan /play menjalankan satu putaran. Route /session dan /verifysession menghasilkan session ID serta token lokal.

Kontrak API hasil capture disimpan pada field apiContract di manifest dan field contract di api-map.json. Kontrak mencatat version, kind, confidence, method, URL, origin, path, queryKeys, request headers yang sudah disaring, request body terbatas, status response, content type, response headers yang sudah disaring, top-level response keys, dan bentuk field response. Header sensitif seperti Authorization, Cookie, Set-Cookie, X-Api-Key, dan proxy-auth tidak disimpan dalam bentuk asli; nilainya diganti dengan <redacted>.

Setiap kontrak memiliki order capture dan dapat dirangkum menjadi replaySequence pada api-map.json. Router lokal mendukung mode replay untuk mencocokkan method dan path, kemudian mengembalikan snapshot response asli jika tersedia. Jika method tidak cocok, router mengembalikan API_CONTRACT_MISMATCH. Mode replay berguna untuk menguji response asli secara berurutan, sedangkan mode emulator stateful berguna untuk mengubah saldo dan menjalankan spin lokal.

Emulator dapat menerima apiContract melalui opsi createStatefulApiEmulator({ apiContract }), menyimpannya dalam snapshot, serta memakai target.path dan kind untuk mengenali endpoint game khusus yang tidak memakai nama /init, /balance, atau /spin standar.

3. STATE YANG DISIMPAN
State mencakup sessionId, token, balance, currency, round, lastWin, history maksimal 50 hasil, phase, lastAction, freeSpins, dan bonusMultiplier. State machine dasar menggunakan fase NEW → SESSION_READY → READY → RESULT. Spin hanya dapat dilakukan setelah session dan init berhasil. Endpoint /result atau /settle mengembalikan hasil spin terakhir. Request yang tidak mengikuti urutan menghasilkan INVALID_STATE HTTP 409, kecuali strictSequence dimatikan untuk kompatibilitas legacy.

Free spin dasar dapat berjalan tanpa charge saldo ketika freeSpins tersedia. Payout match sesuai bonusTriggerMatch dapat menambah freeSpins sampai maxFreeSpins. Fitur bonus ini masih sandbox generik dan bukan aturan provider asli.

State mencakup sessionId, token, balance, currency, round, lastWin, dan history maksimal 50 hasil. Saldo dikurangi sesuai nilai bet sebelum spin dan ditambah kembali sesuai win. Hasil spin memakai pseudo-random generator deterministic berdasarkan seed sehingga urutan hasil dapat diulang saat seed yang sama digunakan.

Aturan spin dasar sekarang memakai payoutTable yang dapat dikonfigurasi. Default payoutTable adalah 3 simbol sama = 5x bet dan 2 simbol sama = 1x bet. Emulator mengembalikan balanceBefore, charged, win, winAmount, totalWin, payoutMultiplier, matchedSymbols, outcome, symbols, reels, rl, dan roundId. Bet divalidasi terhadap minBet, maxBet, dan saldo. Bet tidak valid menghasilkan HTTP 400, sedangkan saldo tidak mencukupi menghasilkan HTTP 409.

Payout ini hanya aturan sandbox dasar. Aturan provider asli seperti paylines, scatter, wild, bonus, free spin, jackpot, multiplier khusus, dan server-side RNG belum otomatis direkonstruksi. Untuk game tertentu, payoutTable dan response schema harus diganti berdasarkan kontrak API serta aturan game yang berhasil dicapture.

4. CARA PEMAKAIAN LOKAL
Import createStatefulApiEmulator dari src/offline/stateful-api-emulator.js untuk memakai handler secara langsung. Gunakan installStatefulApiEmulator() pada sandbox browser atau test lokal untuk memasang interceptor global fetch. Contoh endpoint: fetch('/init'), fetch('/balance'), lalu fetch('/spin', { method: 'POST', headers: {'Content-Type':'application/json'}, body: JSON.stringify({bet: 100}) }). Panggil emulator.snapshot() untuk melihat state terakhir.

5. PERSISTENSI, RESET, DAN REPLAY STATE
Emulator sekarang memiliki storage adapter dengan fallback memory untuk test lokal dan dukungan localStorage ketika berjalan di browser. Gunakan opsi storage dan storageKey untuk menentukan tempat penyimpanan. Fungsi persist() menyimpan state sandbox, loadPersisted() memulihkan state, clearPersisted() menghapus state, reset() mengosongkan session dan history, sedangkan replay() mengembalikan PRNG ke seed awal agar urutan hasil dapat diuji ulang.

Token tidak disimpan ke storage persistence. Saat state dipulihkan, token sandbox yang sedang aktif dipertahankan. Jangan menggunakan storage ini untuk menyimpan credential produksi, cookie, Authorization header, atau data pribadi.

6. VALIDASI OFFLINE PENUH DAN BATASAN KOMPATIBILITAS
Modul src/offline/offline-validation.js menyediakan validasi alur session → init → balance → spin → balance-after dengan mode offline. Harness memeriksa status response, sessionId dan token, saldo sebelum dan sesudah, roundId, history, arithmetic saldo, serta memastikan tidak ada request yang lolos ke fallback network. Jika semua syarat terpenuhi, status menjadi FULL_OFFLINE_READY. Jika ada kegagalan, status menjadi NOT_READY dan detail kegagalan tersedia pada failures.

Validasi ini tidak membuktikan semua aturan provider asli. Emulator tetap belum mengetahui paylines, bonus, free spin, jackpot, validasi signature, WebSocket, SSE, autentikasi server, atau format khusus provider tertentu. Nilai saldo dan hasil spin hanya untuk sandbox, tidak boleh digunakan untuk taruhan, pembayaran, atau sistem produksi. Game yang tidak dikenal oleh api-map harus diblokir pada mode offline atau diteruskan ke network pada mode hybrid.

7. PENGUJIAN DAN KRITERIA BERHASIL
Test minimal harus memverifikasi init mengembalikan saldo, balance membaca saldo yang sama, spin mengurangi atau menambah saldo secara konsisten, bet invalid mengembalikan status 400, saldo tidak cukup mengembalikan status 409, roundId bertambah, dan history tersimpan. Keberhasilan emulator tidak berarti seluruh game kompatibel; game tetap perlu diuji dengan request body, response schema, dan urutan endpoint asli.
