1. GAMBARAN SISTEM SEKARANG
--------------------------------------------------------------------------------

Stack:
  - Frontend PWA     : public/index.html, sw.js, manifest.json
  - Worker CF        : src/index.js (collect, API, AI, history, resume, progress)
  - Modul            : src/collect/*, classify/*, analyze/*, package/*, history/*,
                       progress/*, repair/*, ai.js
  - GitHub Actions   : scripts/collect.js + .github/workflows/collect.yml
  - Deploy           : wrangler.jsonc → Cloudflare Workers + Browser Rendering
  - Storage          : KV GC_HISTORY (sudah di-bind), R2 opsional, artifact GH

Alur collect:
  UI → POST /api/collect (Worker Playwright)
     → jika ZIP besar / limit → POST /api/github/collect → Actions → artifact
  Workspace load ZIP → analisis → repair → preview (sandbox / hybrid)

4. CUSTOM DOMAIN (SERVER / DOMAIN BARU)
--------------------------------------------------------------------------------

  Tidak perlu ubah logika collect. Yang perlu:

  A. Cloudflare Dashboard (akun baru)
     1. Workers → deploy worker (nama bebas)
     2. Settings → Domains & Routes → Add Custom Domain
        contoh: collector.domain-baru.com
     3. DNS: CNAME ke workers (otomatis jika domain di CF)
     4. KV: buat namespace baru → isi id di wrangler.jsonc → redeploy
     5. (Opsional) R2 bucket → bind COLLECTOR_BUCKET
     6. Browser Rendering: enable di account
     7. Secrets: GITHUB_TOKEN, dll. via `wrangler secret put`

  B. Kode yang membantu portability (TAMBAHKAN)

     // wrangler.jsonc — contoh vars
     "vars": {
       "GH_OWNER": "frostbyte-lab",
       "GH_REPO": "frostbyte-lab-game--collector",
       "GH_WORKFLOW": "collect.yml",
       "PUBLIC_APP_NAME": "Game Collector Pro"
     }

     // src/index.js — jangan hardcode owner/repo
     const GH_OWNER = env.GH_OWNER || "frostbyte-lab";
     const GH_REPO  = env.GH_REPO  || "frostbyte-lab-game--collector";

  C. CORS (jika UI dipisah domain lain)
     Saat ini UI = assets Worker (same origin) → CORS tidak masalah.
     Jika nanti frontend di domain lain:
       Response API harus header:
         Access-Control-Allow-Origin: https://ui.domain-baru.com
         Access-Control-Allow-Methods: GET, POST, DELETE, OPTIONS
         Access-Control-Allow-Headers: Content-Type, Authorization
       Handle OPTIONS preflight di fetch handler.

  D. Frontend
     Semua fetch ke `/api/...` (relative) → otomatis ikut domain baru.
     Cek tidak ada hardcode workers.dev di public/index.html (previewBaseUrl
     sudah window.location.origin → OK).

10. RISIKO & BATASAN (TETAP BERLAKU DI SISTEM BARU)
--------------------------------------------------------------------------------

  - Spin/bet/result tidak ada di ZIP jika tidak pernah di-trigger
  - Canvas-only game: fallback koordinat bisa meleset
  - Browser Rendering quota & 429 di Worker
  - ZIP besar tanpa R2 → andalkan GitHub Actions artifact
  - Offline 100% tidak realistis jika logic hanya di server
  - Jangan mengklaim bypass DRM / login orang lain
